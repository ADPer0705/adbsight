01 // Rust TUI Android Deep Inspector

ADBSight

A fast, non-blocking Rust + Ratatui terminal inspector for Android devices over USB and Wi-Fi ADB. Built to see everything on your phone — from batched live CPU/RAM/thermal telemetry and streaming Logcat to APK permissions, filesystems, and personal databases — with embedded SQLite snapshots and JSON/CSV/Markdown exports.

02 // Getting Started

Installation & Quick Start

You can download the prebuilt Linux v1.0.0 release binary directly or compile from source on Linux, macOS, or Windows with Rust 1.88+.

bash — build & run from source
git clone https://github.com/ADPer0705/adbsight.git
cd adbsight

# Try the built-in simulated Android 15 device immediately (no phone needed)
cargo run --release -- --demo

# Or launch against your real USB / Wi-Fi devices
cargo run --release
bash — install v1.0.0 binary on Linux x86_64
curl -LO https://github.com/ADPer0705/adbsight/releases/download/v1.0.0/adbsight-v1.0.0-x86_64-unknown-linux-gnu.tar.gz
tar -xzf adbsight-v1.0.0-x86_64-unknown-linux-gnu.tar.gz
./adbsight --version

ADB Binary Auto-Discovery

Even if adb is not on your shell PATH, adbsight automatically locates Android Platform-Tools in this priority order:

  1. --adb-path <PATH> CLI flag or adb_path in config.toml
  2. System PATH
  3. $ANDROID_HOME/platform-tools/adb and $ANDROID_SDK_ROOT/platform-tools/adb
  4. Standard SDK directories: ~/Android/Sdk/platform-tools/adb (Linux), ~/Library/Android/sdk/platform-tools/adb (macOS), and %LOCALAPPDATA%\Android\Sdk\platform-tools\adb.exe (Windows)
03 // Remote Wireless ADB

Wireless Debugging & QR Pairing

Press w anywhere in adbsight to open the Wireless Debugging & Device Manager. Every wireless workflow supported by modern Android is built directly into the TUI.

1. QR Code Pairing (Android 11+)

Press w → Tab to open the QR Code Pair view. adbsight generates a random service & password payload (WIFI:T:ADB;S:adbsight-...;P:...;;), renders a scannable Unicode half-block QR code in your terminal, watches adb mdns services every second, and automatically runs adb pair followed by adb connect.

2. mDNS Auto-Discovery & Bookmarks

Devices broadcasting _adb-tls-connect._tcp or _adb-tls-pairing._tcp appear automatically in section [2]. Once connected, Wi-Fi endpoints are bookmarked in config.toml for one-Enter reconnection.

3. One-Key USB → Wi-Fi Handoff

Have a phone plugged in over USB? Select it in the Wireless modal and press t. adbsight reads the device's wlan0 IPv4 address, executes adb tcpip 5555, and connects wirelessly so you can unplug the cable.

4. Manual Pair Code & Direct IP:Port

Switch to tab 3 in the Wireless modal to enter an endpoint (192.168.1.42:37185) and optional 6-digit pairing code, or connect directly on startup via adbsight --connect 192.168.1.42:5555.

PHONE SETUP FOR QR PAIRING
On Android 11+, enable Settings → Developer options → Wireless debugging, tap Pair device with QR code, and point your camera at the terminal QR code. Make sure your laptop and phone are on the same Wi-Fi subnet (not AP-isolated).
04 // Privilege & Safety

Root-Aware Inspection

adbsight works out of the box on stock, unrooted Android devices. Upon connecting, it checks id -u and which su to report USER, ADB-ROOT, or SU-ROOT in the top-right status bar.

  • Press R to toggle Root Mode on rooted devices or emulators.
  • When enabled, shell probes, process tables, dumpsys, /data directory listings, and protected content providers (content://sms, content://call_log/calls) transparently elevate through adbd root or su -c.
  • All modifying or destructive actions (Kill PID, Force-Stop, Clear App Data, File Push, Reboot) require explicit confirmation via a modal prompt.
05 // Deep Inspector

The 8 Inspector Modules

[1] Dashboard

Device identity, SELinux & verified-boot state, CPU total + per-core sparkline, RAM/Swap gauges, battery health/voltage/current/temp, thermal zones, storage mounts, and Wi-Fi RX/TX sparkline — fetched in one batched ADB probe per tick.

[2] System & Hardware

Four sub-tabs (Tab): searchable getprop, settings (system/secure/global), hardware sensors (dumpsys sensorservice), and an interactive dumpsys service viewer.

[3] Processes & Services

Live ps table sortable (s) by CPU%, RAM, PID, or Name, plus active Android service records from dumpsys activity services and confirmed SIGKILL (K).

[4] Packages & Apps

Filter All/User/System packages (f), press Enter to inspect SDK levels, installer, granted/denied permissions, launch (l), pull APK (p), force-stop (x), or clear data (c).

[5] Live Logcat

Streaming logcat -v threadtime ring buffer with instant level filters (v/d/i/w/e/f), text search (/), pause (Space), tail (G), clear (C), and export (E).

[6] Filesystem Explorer

Browse /sdcard (d), /data/local/tmp (t), and / with permissions, symlinks, 32 KiB file preview (Enter), pull (p), and confirmed push (u).

[7] Personal Data

Carries over Contacts, SMS (comma & newline-safe parser), Call Logs, and Accounts from the original C# app, plus Android 10–15+ permission diagnostics and message detail viewer.

[8] Shell & Action Deck

Embedded interactive ADB shell with command history (↑/↓) alongside quick actions: PNG screenshot (F2), reboot (F3), SQLite snapshot (F4), and remote text input (Ctrl+I).

06 // Persistence & Automation

SQLite Snapshots, Exports & Headless CLI

Unlike the original C# app's external SQL Server LocalDB requirement, adbsight bundles SQLite directly (WAL mode, zero external setup).

  • Press S to save a labeled full device snapshot to SQLite (with deduplicated personal data tables).
  • Press H to open Snapshot History and inspect any captured device snapshot offline, even after unplugging the phone.
  • Press e to export the active tab (JSON/CSV) or a complete JSON / formatted Markdown inspection dossier to ./exports/.
bash — headless CLI subcommands
# List USB, Wi-Fi, and mDNS wireless devices
adbsight devices

# Capture a full Markdown report headlessly and save to SQLite
adbsight dump --format md --out pixel9_report.md --save-db --label "baseline"

# Run headless dump against the built-in demo simulator
adbsight --demo dump --format json --out demo_snapshot.json

Architecture

module layout

├── main.rs            # CLI parser, file-only tracing, panic-safe ratatui terminal lifecycle
├── cli.rs             # clap derive flags (--serial, --connect, --demo, devices, dump)
├── models.rs          # Shared Serialize/Deserialize domain models
├── adb/
│   ├── discovery.rs   # Cross-platform adb & mDNS binary auto-discovery
│   ├── wireless.rs    # WIFI:T:ADB QR payload & Unicode half-block matrix renderer
│   ├── cli_backend.rs # Non-blocking tokio::process ADB client + streaming logcat

├── storage/
│   ├── config.rs      # TOML config & saved Wi-Fi device bookmarks
│   ├── db.rs          # Bundled WAL-mode SQLite snapshot & deduplicated personal data DB
│   └── export.rs      # JSON, RFC-4180 CSV, and Markdown inspection dossier exporters
├── app/               # Async state machine, background worker pool, key/mouse handlers
└── ui/                # Ratatui 0.30 dark cyber-inspector theme, 8 tabs, and modals
09 // FAQ & Diagnostics

Troubleshooting

SMS / CALL LOGS EMPTY ON ANDROID 10–15+?
Modern stock Android blocks the unprivileged shell UID from reading content://sms and content://call_log/calls. adbsight detects this SecurityException automatically and surfaces a provider notice — press R on a rooted device/emulator to unlock full access.
  • QR pairing times out after scanning: Ensure UDP port 5353 (mDNS) is open in your host firewall and your phone & workstation are on the same Wi-Fi network without client isolation.
  • adb not found: Install Android SDK Platform-Tools or pass --adb-path /path/to/adb.
  • Need to view runtime logs? Logs never write to the terminal while the TUI is running; inspect adbsight.log in your OS local data directory (e.g. ~/.local/share/adbsight/adbsight.log on Linux).
